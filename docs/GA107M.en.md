# GA107M RTX 3050 Ti Laptop port (branch `ga107m-3050ti`)

**English only.** This branch adapts the exact-card unlock transaction to an
HP RTX 3050 Ti Laptop GPU (GA107M) on Windows, using the USB preflight ->
exact-card profile -> experimental manual unlock workflow of this repository.
The RTX 3090 FE case remains the only hardware-verified upstream profile;
nothing here adds hardware support by itself.

## Target card

| Item | Value |
|---|---|
| GPU | NVIDIA GeForce RTX 3050 Ti Laptop GPU, 4 GiB |
| PCI identity | `10de:25a0`, subsystem `103c:88e5`, BDF `0000:01:00.0` |
| VBIOS | `94.07.3a.00.6e` |
| Chip / memory register | pinned from this card's preflight REPORT (expect PMC_BOOT_0 GA107M, memory reg `0x1000`) |
| iGPU display | Intel Iris Xe `8086:9a49` / `103c:88e5` at `0000:00:02.0` |
| Verified driver | 617.14 (unchanged by any phase) |
| Measured lock | FP16/BF16 ~513, TF32 ~252 ops/SM/clk at 20 SM (locked class; unlock target ~1024 / ~512) |

The GA107 firmware path is the GA102 one used by this repo's vendored core:
the official 610.43.03 HAL selects the GA102 Booter/GSP binaries for GA107, and
[IHaBiS02/ga107-unlock](https://github.com/IHaBiS02/ga107-unlock) verified the
same transaction on an LG RTX 3050 laptop. This branch ports that port's
laptop-specific FWSEC fix into the vendored core (see CHANGES.md).

## Phases

1. **Preflight inventory (read-only).** `unlock/build-wsl.sh` (or
   `unlock/build.ps1` with LLVM 20.x on Windows) builds
   `GA107M-PREFLIGHT.EFI`. Copy `usb-staging` to a FAT32 stick, disable
   Secure Boot (suspend BitLocker first if used), boot the stick via F9, and
   return to Windows. One boot produces `GA107M-PREFLIGHT\RUNnn\REPORT.TXT`
   (config dump, BAR0 descriptor, PROM SHA-256, FWSEC parse, cold registers,
   GOP classification) and `PROM.BIN`. No GPU writes, DMA, reset, ownership
   change or driver release exist in this build.
2. **Profile transcription.** Run
   `python tools/ga107m-parse-preflight.py RUNnn\REPORT.TXT`, review the
   sanity findings (FWSEC `0x400` engine mask, DMEM round-up `ret=0`,
   zero NVIDIA GOPs, 16 MiB BAR0), and transcribe the emitted pins into
   `unlock/port.h`, then define `GU_CARD_PROFILE_PINNED 1`.
3. **Experimental manual unlock.** Build with
   `-ExperimentalUnlock -StockProfile entryLatchedSs1Preserve` (SS0-only,
   the ga107-unlock default policy; `entryLatchedSs1Full` adds the guarded
   SS1=0x8 TF32 experiment). The app refuses to build until phase 2 is
   complete (`#error` in `port.h`), re-verifies the exact-card profile,
   requires a live `U` keypress (Esc or 30 s timeout cancels), performs the
   one-shot transaction, and returns without a reset so Windows boots with
   the selectors applied.
4. **Verification.** In Windows, run the clock-normalized GEMM benchmark
   (`bench_locked.py` in the session workspace) before and after: FP16/BF16
   ops/SM/clk should move from the ~512 class toward ~1024 (TF32 from ~256
   toward ~512 only with the SS1 opt-in). Suspend/shutdown clears the
   selectors; re-run the unlock boot to reapply.

## Safety properties retained from upstream

Fail-closed guards, one-shot manual confirmation, entry-latched selector
verification, DMA/FLR containment, STOP/POWER OFF halt on unsafe return,
USB-only media, Secure Boot required off, and no VBIOS flashing. The laptop
display stays on the Intel iGOP throughout; the unlock target must expose no
active GOP (v1 policy).

## Limits

One laptop, one VBIOS, evidence first. Power-limited laptop silicon will not
sustain a full 2x in real workloads; the LG 3050 measured +33-35% GEMM and
+26% ComfyUI throughput. Long-term stability, sleep/resume and repeated
automatic boot are not established by this port.
